## [Unreleased]

## [2.6.0] - 2026-10-15

Five new skills (24 in total). Each was written against the library source and a generated Phoenix 1.8.15 app, and its examples were run: generators in a scratch app, migrations against PostgreSQL 16 with a 2M-row table, queries against Postgres, Req clients in a test project, Tailwind builds with the real binary.

### Added — skills
- **phoenix-scopes-and-generators**: the generated `%Scope{}`, every `config :scopes` key (including `route_prefix`, `route_access_path`, `schema_migration_type`), `phx.gen.*` with `--scope`/`--no-scope`, adding an org scope end to end (struct, config entry, plug + `on_mount`, test helpers), scoped JSON pipelines, adopting scopes in a pre-1.8 app.
- **phoenix-tailwind-daisyui**: Tailwind v4 in `app.css` (`@source`, `@plugin`, no `tailwind.config.js`), why interpolated class names produce no CSS, daisyUI (a sparse git dependency, not npm) themes and dark mode, extending `core_components` (`class` replaces defaults, `<.icon>` has no `:rest`, `type` needs adding to `include:`), `Layouts.app`, accessibility gaps in generated code.
- **ecto-migrations-safety**: concurrent indexes need both `@disable_ddl_transaction` and `@disable_migration_lock` (with only the first, the build waits forever on the migration lock), `lock_timeout` via `after_begin/0`, NOT NULL and foreign keys via `NOT VALID` + `VALIDATE` (`modify … null: false` still scans the table), volatile defaults rewrite tables, batched schemaless backfills, expand-and-contract renames.
- **ecto-queries-performance**: N+1 detection, separate vs join preloads and per-parent limits, `dynamic`/`subquery`/`exists`, counting (`Repo.aggregate` raises on `group_by`), `Repo.stream` inside `Repo.transact`, `FOR UPDATE`/`SKIP LOCKED`/`optimistic_lock`, `insert_all` (no autogenerated timestamps, 65,535-parameter limit), `Repo.explain` (aborts an enclosing transaction unless `wrap_in_transaction: false`), `prepare_query/3` tenancy guards.
- **http-clients-req**: client modules on Req 0.7, retry semantics (`:safe_transient`, uncapped `Retry-After`, `retry_delay` disables it), timeouts (`request_timeout`, `finch: [pool_timeout:]`, real 5 s connect default), JSON needs Jason, custom auth headers survive cross-host redirects, idempotency keys, Finch pools, `Req.Test` allowances, telemetry, circuit breaking, upgrading from Req 0.5.
- Existing skills route to the new ones where they overlap, and contradictions with the new findings were fixed.

### Added — tooling
- GitHub Actions CI: hook and packaging suites on Ubuntu and macOS (`/bin/bash` 3.2), shellcheck, the `code_quality.exs` suite, and `dev/check_snippets.exs` inside a freshly generated Phoenix 1.8 app (`EPG_REQUIRE_HEEX=1` makes it fail rather than skip HEEx blocks when LiveView isn't loaded).
- Skill frontmatter lint in `tests/packaging/run_tests.sh`: only `name`/`description`, name matches the directory, unique "Use when…" descriptions, and a "Verified against" line under each H1.
- CI installs the plugin with the real Codex CLI (`codex plugin add`) and checks every skill arrives.
- README documents installing in Codex with `codex plugin marketplace add j-morgan6/elixir-phoenix-guide` + `codex plugin add elixir-phoenix-guide@elixir-phoenix-guide` (verified); `install-codex.sh` remains for setups without the plugin system.

### Changed
- `dev/check_snippets.exs` flags `<:actions>` only inside `<.form>` (`<.header>` has a real `:actions` slot) and supports `EPG_REQUIRE_HEEX=1`.

## [2.5.0] - 2026-10-15

Every skill re-verified against the library source and Phoenix 1.8's generators (Elixir 1.20.2, Phoenix 1.8.15, LiveView 1.2.12, phoenix_html 4.3, Ecto 3.14.2, Oban 2.24.2, Req 0.7.5, Plug 1.20.3). Each SKILL.md now opens with a "Verified against" line.

### Fixed — examples that didn't compile, render or work
- `<:actions>` inside `<.form>` (a slot `form/1` doesn't declare) silently dropped the submit button in four places; forms now put `<.button>` inside and always carry an `id`.
- Removed `text_to_html` (gone in phoenix_html 4), the undefined `put_password_hash`, `<.label>` (not in 1.8 core components), an unassigned `@form`, and a `def … do: # …` body that didn't parse.
- Telemetry handler without a catch-all clause (telemetry detaches it on the first unmatched event); local captures replaced with `&__MODULE__.handle_event/4`.
- `config :logger, :console` (ignored when `:default_formatter` is set, as in Phoenix 1.8) replaced with `:default_formatter` / `:default_handler`.
- Removed lines that overwrote `Plug.RequestId`'s request id in Logger metadata.
- Upload tests now assert on `render_upload/3`'s return value; test examples use real fixtures, `ConnCase` where `conn` is needed, and 1.8 routes.
- Ecto: soft delete that silently did nothing, `Repo.one` "get first", an insert_all test that could never match, an email-downcase test with no downcase.

### Fixed — Phoenix 1.8 `phx.gen.auth` accuracy
- `on_mount(:require_authenticated, …)` (the plug and `live_session` keep the `_user` name); `get_user_by_session_token/1` returns `{user, inserted_at}`; `@current_scope` is `nil` for guests.
- Log-in stays reachable for logged-in users (sudo mode re-authenticates there); no guest-only `live_session`.
- Registration is email-only (magic link): custom fields go in a new `registration_changeset/3` that pipes `email_changeset/3`, so changing email keeps working; generated fixtures are reused instead of rewritten.
- Password length uses phx.gen.auth's `min: 12, max: 72` plus `count: :bytes` (bcrypt's limit is bytes).

### Security
- Every context call takes `%Scope{}` first, as the 1.8 generators do; no record is loaded or deleted by a client id alone (IDOR). Authorization also runs in `handle_params`.
- New rule: never `cast` foreign keys or privileged fields (`:user_id`, `:role`, `:confirmed_at`…).
- PubSub topics are per-scope (`"user:#{id}:posts"`), not global.
- Uploads: stored extension comes from an allowlist matched against the file's magic bytes, never the client (stored-XSS fix); downloads are scoped by record id with an allowlisted content type and `attachment` disposition.
- Open redirects: the risk is `redirect(external:)`, not `to:` (which Phoenix already restricts). SQL-injection guidance now covers user-chosen columns and `Repo.query` interpolation.
- JSON API: hashed, expiring bearer tokens; rate-limited login; safe `per_page` parsing; stable ordering and keyset pagination.
- Channels: socket token only for logged-in users, explicit `max_age`, disconnect on logout. LiveDashboard behind `dev_routes` or auth. Health checks no longer leak error details. Real CSP example (Phoenix's default only sets `base-uri`/`frame-ancestors`).

### Changed — skills
- `Repo.transact/2` replaces `Repo.transaction/2`; streams are the default for collections; HEEx uses `{…}`, `:for` and `:if`; one logging rule across skills (filterable values in metadata).
- **phoenix-liveview-essentials**: forms (`to_form`, `used_input?`, `phx-debounce`), `assign_async`/`start_async`/`stream_async`, JS commands, colocated hooks, `:key`, `<.portal>`; new `js-interop.md`.
- **elixir-essentials** cut from 425 to ~175 lines and gains a "Modern Elixir (1.18+)" section (type checker, `JSON`, `dbg`, `Process.set_label/1`).
- **otp-essentials**: `call` by default, `:protected` ETS, PartitionSupervisor, `GenServer.reply/2`, task timeouts.
- **oban-essentials**: unique `fields` keep `:worker`, `states: :incomplete`, Oban 2.24 top-level `cron:`/`pruner:`/`lifeline:` config, transactional enqueue, capped snoozes, SSRF-safe HTTP worker, OSS vs Pro.
- **ecto-***: `timestamps(type: :utc_datetime)`, correct upserts (`returning: true`), escaped `ilike`, reversible migrations, case-insensitive unique email, `inputs_for` sort/drop params; `cast_assoc` lives only in ecto-nested-associations.
- **deployment-gotchas**: `mix phx.gen.release --docker`, Dockerfile order, conditional `PHX_SERVER`, SSL, rolling-deploy migration order, Oban queues per node.
- **telemetry-essentials**: metric-tag cardinality, `:telemetry_test`, OpenTelemetry, project telemetry wrappers.
- **testing-essentials**: Mox with `verify_on_exit!`, `Req.Test`, LiveView async/navigation helpers, LazyHTML, `parameterize:`, sandbox allowances.
- Reference docs moved next to the skills that use them, where Claude can actually read them: `ecto-essentials/reference.md`, `phoenix-liveview-essentials/checklist.md`, `elixir-essentials/project-structure.md`, `testing-essentials/reference.md` (`docs/reference/` removed; `ecto-conventions.md` folded into the Ecto skills).
- Skill descriptions rewritten as "Use when… Not for…" so overlapping skills don't compete.

### Changed — hooks and scripts
- File checks report **only the lines the tool call changed** (Edit: where `new_string` landed; Write: `git diff`), evaluated with whole-file context. Comments and `@doc` text are ignored; `deps/`, `_build/`, `node_modules/` are skipped.
- Two tiers: near-certain bugs block (exit 2); heuristics arrive as advisory `additionalContext`.
- `@impl` no longer flags later clauses of a multi-clause callback; open-redirect check targets `external:`; `Repo.query!` interpolation and per-table migration indexes are checked; `form_for` has a word boundary; Logger only flags interpolated secrets; `push_redirect` flagged.
- Bash guard parses each command segment: `MIX_ENV=test mix ecto.reset` and commit messages/greps mentioning it are allowed; `mix ecto.drop`, `-uf`, `+refspec`, `git -C … push --force` are caught; opt out with `EPG_ALLOW=force_push|ecto_reset|ecto_drop`; only active in Elixir projects.
- Matcher covers `MultiEdit` (older Claude Code versions).
- SessionStart reports locked versions from `mix.lock` (plus the requirement), detects scopes from the code rather than the version, handles umbrellas and plain libraries, warns when `jq` is missing, and reads the plugin version from `VERSION`.
- `code_quality.exs`: the unused-function detector (wrong on `?`/`!` names and function components) is removed — use `mix compile --warnings-as-errors` and `mix xref`; "ABC" renamed to branch complexity; duplication now compares normalized bodies across the whole tree. `run_analysis.sh` works at an umbrella root.
- Hook test suite grew from 33 to 134 checks.

### Removed
- `file_patterns` and `auto_suggest` frontmatter (Claude Code never read them).
- Version strings outside `VERSION` and `plugin.json`.

### Maintainer
- `dev/check_snippets.exs` parses every `elixir`/`heex` block in the skills and flags known regressions; `dev/sync_copilot.sh` (moved from `scripts/`) now also regenerates the Copilot `AGENTS.md` from skill reference files.
- `install.sh` asks before deleting a legacy install.
- `CLAUDE.md.template` no longer points at nonexistent `docs/reference/` paths and recommends `compile_env`/`runtime.exs` correctly.

## [1.2.0] - 2026-02-12

### Breaking Changes
- **Plugin renamed** from `elixir-optimization` to `elixir-phoenix-guide`
  - Better reflects purpose: essential guide for ALL Elixir work, not just optimization
  - Update marketplace references and installation commands
  - Reinstall required for existing users

### Changed
- **Skills consolidated from 8 to 4** for reduced friction:
  - `elixir-essentials` (merged elixir-patterns + error-handling)
  - `phoenix-liveview-essentials` (merged phoenix-liveview + liveview-lifecycle)
  - `ecto-essentials` (renamed from ecto-database)
  - `phoenix-uploads` (merged in phoenix-static-files content)
  - Removed skill-discovery meta-skill (no longer needed)

- **RULES sections added** to all skills:
  - 7-8 non-negotiable rules at the top of each skill
  - Rules visible in 10 seconds, reference examples below
  - Agents internalize rules, reference examples when needed

- **Skill descriptions shortened and strengthened**:
  - Changed from "INVOKE BEFORE" to "MANDATORY for ALL"
  - Removed feature lists that enable rationalization
  - Single-sentence descriptions using forceful language
  - Example: "MANDATORY for ALL Elixir code changes. Invoke before writing any .ex or .exs file."

- **CLAUDE.md template updated** with enforcement section:
  - Mandatory rules block added to template
  - Specifies exact skill invocation requirements per file type
  - Explicit "not optional" language
  - Projects adopting template get built-in enforcement

- **Reminder hook added**:
  - Non-blocking (exit 0) reminder on .ex/.exs/.heex writes
  - Prompts agent to verify skill invocation
  - Gentle nudge without preventing work

### Documentation
- **Metadata limitations documented**:
  - README now clarifies auto_suggest and file_patterns are forward-looking
  - Noted as pending Claude Code runtime support
  - False expectation claims removed from v1.1.0 changelog references

### Impact
- Reduced cognitive load: 4 skills vs 8 means less choice paralysis
- Improved adoption: MANDATORY language harder to rationalize away
- Better enforcement: CLAUDE.md template + hooks + reminders create multiple touchpoints
- Clearer purpose: "guide" name indicates this applies to ALL work, not just performance tuning

### Migration Notes
For existing users:
1. Uninstall `elixir-optimization` plugin
2. Install new `elixir-phoenix-guide` plugin from marketplace
3. Update project CLAUDE.md files if using template
4. Skill invocations use new names with same plugin prefix

## [1.1.0] - 2026-02-09

### Added
- **skill-discovery meta-skill** - Systematic checklist for identifying applicable skills
  - File type detection for automatic skill suggestion
  - Task type detection for process skills
  - Priority-ordered skill invocation guide
  - Example workflows for common scenarios
  - Marked as priority 1 skill to invoke first

### Changed
- **All 7 existing skills updated** with mandatory "INVOKE BEFORE" language:
  - elixir-patterns: "INVOKE BEFORE writing any Elixir code"
  - phoenix-liveview: "INVOKE BEFORE implementing any LiveView feature"
  - ecto-database: "INVOKE BEFORE modifying any Ecto schema, query, or migration"
  - error-handling: "INVOKE BEFORE implementing error handling"
  - phoenix-uploads: "INVOKE BEFORE implementing file upload functionality"
  - phoenix-static-files: "INVOKE BEFORE serving uploaded files or static content"
  - liveview-lifecycle: "INVOKE BEFORE working with LiveView rendering phases"

- **File pattern metadata added** to all skills:
  - Skills now include file_patterns array for automatic detection
  - auto_suggest: true flag enables proactive skill suggestions
  - Pattern matching for .ex, .exs, .heex files and specific directories

### Impact
- Expected 50%+ increase in skill usage through forcing language
- Automatic skill suggestions when editing relevant files
- Systematic skill discovery prevents missing applicable guidance
- Better developer experience with proactive skill recommendations

## [1.0.0] - 2026-01-26

### Added
- **7 Skills** for Elixir and Phoenix development:
  - `elixir-patterns` - Pattern matching, pipes, with statements, naming conventions
  - `phoenix-liveview` - LiveView lifecycle, events, uploads, PubSub, navigation
  - `ecto-database` - Schemas, changesets, queries, associations, migrations
  - `error-handling` - Error tuples, with statements, supervisors, error boundaries
  - `phoenix-uploads` - File upload configuration, manual vs auto-upload patterns
  - `phoenix-static-files` - Static paths configuration and file serving
  - `liveview-lifecycle` - Render phases, safe assign access, mount initialization

- **10 Hooks** for real-time code quality enforcement:
  - Blocking hooks (5): missing-impl, hardcoded-paths, hardcoded-sizes, static-paths-validator, deprecated-components
  - Warning hooks (4): nested-if-else, inefficient-enum, string-concatenation, auto-upload-warning

- **4 Agent Documentation Files**:
  - `project-structure.md` - Directory layout and context boundaries
  - `liveview-checklist.md` - Step-by-step LiveView development guide
  - `ecto-conventions.md` - Comprehensive Ecto patterns and best practices
  - `testing-guide.md` - Testing patterns for contexts, LiveViews, and schemas

- **Installation Methods**:
  - Claude Code plugin marketplace installation
  - Quick install script
  - Manual installation guide

- **Project Template**:
  - CLAUDE.md.template for project-specific customization

### Documentation
- Comprehensive README with installation and usage instructions
- Hook installation guide (INSTALL-HOOKS.md)
- MIT License
- Installation script (install.sh)
